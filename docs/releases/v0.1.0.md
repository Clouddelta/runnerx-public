# v0.1.0 — Docker backend and data pipeline

This first release packages the RunnerX backend and offline data pipeline as a local Docker Compose application. The repository remains private for development and evaluation; no cloud deployment is required for this release.

## Included

- MySQL 8.4, an explicit Alembic migration step and a non-root FastAPI container with database readiness checks.
- Pydantic API contracts, pagination and filtering for runners, camps, groups, registrations and training sessions.
- Tenant API-key authentication, UUID identities and composite MySQL foreign keys that enforce tenant/camp ownership.
- pandas/openpyxl imports for CSV and XLSX, with English/Chinese headers, whole-batch validation, dry runs, row-level errors and import audits.
- SHA-256 replay detection and updates by stable, case-sensitive external runner IDs.
- Reproducible synthetic fixtures: 30 runners, 30 registrations and 360 training sessions.
- A reusable Compose business acceptance tool that creates fresh QA tenants, uses actual API and import operations, and cleans up its own data.
- A host Python standard-library backup helper, plus checksum-verified restoration into a new isolated database for recovery rehearsal.
- A Docker operations guide covering startup, authentication, custom imports, backup/restore, maintenance and troubleshooting.

## Start

Follow the [Docker guide](../docker-guide.md). The guide uses host API port 8002; the configuration's default remains 8000. API documentation is available at `/docs` after startup.

No host Python or MySQL installation is needed to run the application containers. Any host requirements for optional validation/backup helpers are documented with their commands.

## Verification

The final local suite passed 140 tests, with one Windows symlink-permission skip. The shipped Compose verifier passed all 11 checks and cleaned up its QA rows. A real backup was restored into a separate database and its complete SQL content hash matched the source backup. CI additionally runs these Docker acceptance and restore checks for each change.

Existing release evidence includes a successful Docker build/startup, MySQL migrations, 30-runner/360-session seed, unchanged identities after seed replay and container recreation, and a 93-test Python suite against a dedicated MySQL database. The earlier live business acceptance exercised Excel corrections, atomic rejection and tenant isolation.

See [validation](../validation.md) and [business acceptance](../business-acceptance.md) for execution details and limitations. Those records include the applicable execution environment; simulated deployment checks do not establish a real cloud deployment.

## Compatibility and data

This is the initial release; there is no earlier published migration baseline. The schema uses Alembic revision `0002` at head. New installations run migrations before the API starts.

The database persists in the Compose named volume. Container rebuilds and normal `docker compose down` preserve it. Removing volumes erases the database. Follow the backup and restore procedure before an incompatible schema change.

Inputs must meet the [data contracts](../data-contracts.md). The provided source fixtures are synthetic and are distributed with the code under the repository's MIT license. Application credentials, private inputs, local databases and backup artifacts are excluded from Git by the repository's ignore rules.

## Scope and limits

- The product interface is an API plus administrative CLI; no frontend or fitness-account integration is included.
- A tenant key grants access to that tenant's complete API. Per-user roles and interactive login are outside v0.1.
- Imports execute as administrative CLI jobs; there is no public upload endpoint.
- Docker examples bind to localhost and include public demo credentials. Shared deployments need their own access and credential configuration.
- GCP/Terraform reference files remain in the repository. They are optional, and no real Cloud Run or Cloud SQL deployment is part of this release evidence.
- Throughput, reduced manual effort and zero-downtime behavior have not been measured; this release makes no numeric claims for them.
